# Upgrade the winnow skill bundle to 0.10.0

## What this changes
Nothing an attendee sees. The product-side skills under `.claude/skills/` move from winnow 0.9.0 to 0.10.0, pinned in `apm.yml` and recorded in `apm.lock.yaml`. No application code changes.

## Where
- `apm.yml` — `dependencies.apm`: `quiram/winnow#v0.9.0` becomes `quiram/winnow#v0.10.0`.
- `apm.lock.yaml` — regenerated by `apm install` (not hand-edited): `resolved_ref: v0.10.0`, `version: 0.10.0`, new `resolved_commit`, `deployed_files`, hashes.
- `.claude/skills/` — rewritten by the same `apm install`; any skill directory or file in the 0.9.0 `deployed_files` that the new lockfile no longer lists is deleted. Untracked `scripts/__pycache__/` dirs are not deployed and stay out of the commit.
- `README.md` — the "From meeting to ticket" table (about lines 118-132) names `listen-to-meeting`, `transcribe-audio`, `winnow`, `create-tasks`, `update-context`, `setup-winnow`, `winnow-setup-audio`; edit it only if the regenerated `deployed_files` adds, drops or renames one of these.
- Test: new `tests/unit/winnow-pin.test.js` (node:test, run by `npm test`); it only reads files, so it uses no lane and no `tests/helpers.js`.

## How it will be proved
| Done when | Check | Layer |
| --- | --- | --- |
| `apm.yml` pins `#v0.10.0`; lockfile has `version: 0.10.0` and `resolved_ref: v0.10.0` | `winnow-pin.test.js` reads both files and asserts the pin and both lockfile fields (main has 0.9.0) | unit |
| `.claude/skills/` holds exactly what the lockfile deploys | same test: every `deployed_files` path exists, and every top-level dir in `.claude/skills/` is the first path segment of some `deployed_files` entry (ignoring `__pycache__`) | unit |
| No `0.9.0` outside `specs/` and the lockfile | same test walks the repo (skipping `node_modules`, `.git`, `specs/`, `apm.lock.yaml`, `package-lock.json`) and asserts no file contains `0.9.0`; `apm.yml` fails on main | unit |
| README skill names match the deployed set | same test: every backticked skill name in the README skills table is a directory in `.claude/skills/` | unit |
| `npm test` passes | the full `npm test` run, which includes the new file | unit/API |

## Out of scope
Any change to skill content, application code or the harness workflows. Playwright (`npm run verify`) is not needed: no UI is touched.
