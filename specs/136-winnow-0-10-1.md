# Upgrade the winnow skill bundle to 0.10.1

## What this changes
Nothing an attendee sees. The skills under `.claude/skills/` move from winnow 0.10.0 to 0.10.1, which fixes the `metadata_errors` crash in `transcribe-audio`. No application code changes.

## Where
- `apm.yml` line 12 — `quiram/winnow#v0.10.0` becomes `quiram/winnow#v0.10.1`.
- `apm.lock.yaml` — regenerated by `apm install`, not hand-edited: `resolved_ref: v0.10.1` (line 8), `version: 0.10.1` (line 9), new `resolved_commit`, `deployed_files`, hashes.
- `.claude/skills/` — rewritten by the same `apm install`; anything the new `deployed_files` no longer lists is deleted. Untracked `__pycache__/` dirs stay out of the commit.
- `README.md` — "From meeting to ticket" table; edit only if the regenerated `deployed_files` adds, drops or renames a skill it names.
- `tests/unit/winnow-pin.test.js` — change `VERSION` (line 9) to `0.10.1` and `OLD` (line 10) to `0.10.0`. Both must be built from parts (as `OLD` already is), because the third test walks the repo and a literal `0.10.0` in this file would fail it. Reads files only, so no lane and no `tests/helpers.js`; run by `npm test`.
- Not a code change: `uv run .claude/skills/transcribe-audio/scripts/transcribe.py file <audio>` is run once by hand (the repo's `audio_message.m4a` is untracked and must not be committed).
