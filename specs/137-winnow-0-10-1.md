# Bump the winnow skill bundle to 0.10.1

## What this changes

Nothing an attendee sees. The product-side skills under `.claude/skills/` move
from winnow 0.10.0 to 0.10.1: upstream's audio fixes — `transcribe-audio`'s
`check` now decodes a short generated clip so dependencies that import but
cannot work together are caught, `winnow-setup-audio` runs both readiness
checks, and `listen.py` picks up the matching fix. The pin, the lockfile and
the deployed skill files move together, as a regenerated bundle. No
application code, no README or context-doc change: 0.10.1 adds and removes no
skill, so every list of skill names still reads true.

## Where

- `apm.yml` — line 12, `dependencies.apm`: `quiram/winnow#v0.10.0` becomes
  `quiram/winnow#v0.10.1`.
- `apm.lock.yaml` — regenerated by `apm install`, never hand-edited:
  `resolved_ref: v0.10.1`, `version: 0.10.1`, `resolved_commit:
  bb79f930cd6df37812d49f580cc7fdcd8bb7b57a` (v0.10.1's commit; main has
  `897b92a4…`), and a new `deployed_file_hashes` entry plus matching
  `deployments[].content_hash` for each file 0.10.1 touches. `apm` is not on
  the runner's PATH; install it before building, and do not fake the lockfile.
- `.claude/skills/transcribe-audio/SKILL.md`,
  `.claude/skills/transcribe-audio/scripts/transcribe.py`,
  `.claude/skills/listen-to-meeting/scripts/listen.py`,
  `.claude/skills/winnow-setup-audio/SKILL.md` — rewritten by that same
  `apm install`; these four are the whole upstream delta.
- `tests/unit/winnow-pin.test.js` — `VERSION` (line 9) becomes `'0.10.1'`;
  `OLD` (line 10) becomes `['0', '10', '0'].join('.')`, kept split so the file
  does not match its own repo-wide grep. Add one test, beside the existing
  three, that asserts the lockfile's `resolved_commit` is
  `bb79f930cd6df37812d49f580cc7fdcd8bb7b57a` and that every
  `deployed_file_hashes` line (`/^ {4}(\.claude\/skills\/\S+): sha256:([0-9a-f]{64})$/m`,
  one or more matches required) equals `createHash('sha256')` of that file's
  bytes — verified today against `.claude/skills/winnow/SKILL.md`, so the
  scheme is plain sha256 of the file. The test reads files off disk through
  the `read()` helper already in it: no lane, no browser, nothing from
  `tests/helpers.js`.

## Decisions

- The ticket's rationale is wrong about the fix: 0.10.1 changes only the audio
  skills (`transcribe-audio`, `listen-to-meeting`, `winnow-setup-audio`); the
  tracker-facing `create-tasks` skill is byte-identical to 0.10.0. The bump
  happens anyway — it is the released patch and the pin should track it — but
  the "task tracker integration" claim is not something to verify.
- The pin test gains the `resolved_commit` and on-disk-hash assertions rather
  than checking version strings only, because three version strings can all be
  edited by hand while the skills on disk stay at 0.10.0, which is exactly the
  failure "dependencies are installed" is about.

## Out of scope

This rewrites files under `.claude/skills/`, so `editsHarness` is true and CI
cannot build it: the implementation is a local `apm install` plus the test
edit, pushed from a person's machine. No README or `docs/context/harness.md`
edit — the skill set and the test list they record are unchanged.
