# Upgrade the winnow skill bundle to 0.11.0

## What this changes

Nothing an attendee sees. The skills under `.claude/skills/` move from winnow
0.10.1 to 0.11.0, so an attendee who runs `/winnow` in a fresh fork gets the
current release — the one that can record each conversation it processes. No
application code, no harness workflow.

## Where

- `apm.yml` — line 12, `- quiram/winnow#v0.10.1` becomes `- quiram/winnow#v0.11.0`.
- `apm.lock.yaml` — regenerated by `apm install` from the repo root, never
  hand-edited: `resolved_ref: v0.11.0` (line 8), `version: 0.11.0` (line 9),
  `resolved_commit: 61b77830caa095627a2236eb36471ec1c803f926` (the peeled
  `v0.11.0` tag), new `deployed_file_hashes`, `content_hash` and `deployments`.
  The APM CLI ships a `apm-linux-x86_64` binary on
  `danielmeppiel/apm` releases; the lockfile was last written by 0.33.0.
- `.claude/skills/` — redeployed by the same command. v0.11.0's `skills/` tree
  holds the same nine directories and the same thirteen files as 0.10.1
  (checked against the tag), so only file contents change; nothing is added,
  dropped or renamed.
- `tests/unit/winnow-pin.test.js` — line 9 `VERSION = '0.11.0'`, line 10
  `OLD = ['0', '10', '1'].join('.')`; `OLD` stays built from parts because the
  third test walks the repo and a literal would match itself. In test 2, after
  the existing path checks, assert each deployed file's sha256: parse the
  lockfile's hash map with `/^ {4}(\.claude\/skills\/\S+): sha256:([0-9a-f]{64})$/gm`
  (four spaces, so the `deployments:` block below it does not match) and compare
  against `createHash('sha256')` of the file on disk. Reads files only — no
  Playwright, no lane, no `tests/helpers.js`; run by `npm test`.
- `README.md` — unchanged. It has no "From meeting to ticket" table; the only
  slash commands it names are `/winnow` and `/ship`, and both still resolve
  (`.claude/skills/winnow`, `.claude/workflows/ship.js`).

## Decisions

1. **Criterion 2 already holds on main as written**, and would still hold after
   a no-op: the paths match today, and v0.11.0 adds, drops and renames nothing.
   This build proves the stronger reading instead — every deployed file hashes
   to what the lockfile records, which with test 1's version assertion pins the
   bytes on disk to 0.11.0 rather than merely to a tidy directory listing.
2. The lockfile's `apm_version` moves from 0.33.0 to whichever CLI runs (0.35.0
   today) as ordinary generated output, rather than pinning the old CLI to keep
   that line still.
3. If the APM CLI cannot run in the build environment, copying the tag's
   `skills/` tree verbatim (`gh api repos/quiram/winnow/git/trees/<commit>`) and
   recomputing the lockfile fields and hashes from those exact bytes counts as
   "not hand-edited" — the result is byte-identical to what `apm install` writes.
4. `README.md` is left untouched, since the deployed skill set is unchanged.

## Out of scope

Writing transcript records (its own ticket), application code, harness
workflows, and any context doc describing what 0.11.0 adds.
