# Upgrade the winnow skill bundle to 0.9.0

## What this changes
No attendee-facing change. The product-side skills (winnow) move from v0.8.0 to
v0.9.0. The skills 0.9.0 drops (`process-requirements`, `setup-audio`) leave
`.claude/skills/`, and the README's "From meeting to ticket" section names the
skills that now exist.

## Where
- `apm.yml` — `dependencies.apm`: `quiram/winnow#v0.8.0` -> `#v0.9.0`.
- `apm.lock.yaml` — regenerated by `apm install` (not hand-edited): `version: 0.9.0`, `resolved_ref: v0.9.0`, new `deployed_files` and hashes.
- `.claude/skills/` — the files `apm install` deploys; `git rm -r` `process-requirements/` and `setup-audio/` (apm does not prune them). Add whatever new skills 0.9.0 deploys; the final tree must equal the lockfile's `deployed_files`.
- `README.md` — "From meeting to ticket" (table around lines 121-127 and the `setup-audio` sentence at ~131): replace removed skill names with the skills 0.9.0 actually provides, read from the new `.claude/skills/*/SKILL.md` descriptions. Also fix any other doc found by the grep below.
- Tests: no new test; this is config and docs. `npm test` is the regression check. No lane or `tests/helpers.js` needed (no app or Playwright run).
- Harness: touches files under `.claude/` (`editsHarness`).

## How it will be proved
| Done when | Check | Layer |
| --- | --- | --- |
| apm.yml pins v0.9.0; lockfile records 0.9.0 / v0.9.0 | `grep` apm.yml for `#v0.9.0`, apm.lock.yaml for `version: 0.9.0` and `resolved_ref: v0.9.0` (both say 0.8.0 on main) | shell check |
| `.claude/skills/` equals the lockfile's deployed set; removed skills gone from disk and git | compare `ls .claude/skills` and `git ls-files .claude/skills` against `deployed_files`; `test ! -e` both removed dirs | shell check |
| No `process-requirements` / `setup-audio` outside the lockfile | `grep -rn "process-requirements\|setup-audio" . --exclude-dir=node_modules --exclude-dir=.git --exclude=apm.lock.yaml` is empty (README and skill files match on main) | shell check |
| README names the current skills | every skill named in README's winnow table exists in `.claude/skills/`, and every deployed skill appears | shell check |
| Nothing regressed | `npm test` | unit + API |

## Decisions
Which replacement skills the README should describe depends on what 0.9.0 ships; the builder reads it off the deployed `SKILL.md` descriptions, and keeps the table's Listen/Transcribe/Raise/Remember shape where those skills still exist.

## Out of scope
Application code, the harness workflows, and untracked `__pycache__` directories under `.claude/skills/`.
